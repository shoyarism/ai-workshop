# ADR-005: Git Bailiff Pre-Commit/Pre-Push Enforcement System

## Context

Software quality degrades when:
- Commits bypass local checks
- CI-only gates allow bad code to ship
- Developers work around quality tools
- Post-commit fixes become the norm

Traditional pre-commit hooks are easily bypassed or accidentally committed.

## Decision

Implement a **Git Bailiff** that:
1. Installs as pre-commit AND pre-push hooks
2. Invokes Slop Court on staged files only
3. Blocks commits with sustained felonies (zero-tolerance)
4. Allows misdemeanors with warnings
5. Provides cryptographic proof of acquittal

## Hook Implementation

```bash
#!/bin/bash
# SLOP COURT BAILIFF ENFORCEMENT HOOK v3.5
# Automatically generated by Workshop OS Anti-Slop Court

echo "⚖️  Slop Court Bailiff: Convening Pre-Flight Judicial Review..."

python scripts/workshop_court.py bailiff-check --staged
RESULT=$?

if [ $RESULT -ne 0 ]; then
    echo ""
    echo "❌ CONTEMPT OF COURT: Git operation aborted by order of the Slop Court."
    echo "   Remediate all sustained violations or run: python scripts/workshop.py court reform <file>"
    echo ""
    exit 1
fi

echo "✓ Slop Court: Acquitted (UNANIMOUS). Proceeding with git operation."
exit 0
```

## Enforcement Logic

### Pre-Commit Flow

```
[ Developer runs git commit ]
           ↓
[ Bailiff hook invokes ]
           ↓
[ Slop Court scans staged files ]
           ↓
[ 3-juror bench deliberates ]
           ↓
[ Verdict: ACQUITTED / CONTEMPT ]
           ↓
[ Git operation succeeds or blocks ]
```

### Pre-Push Flow

```
[ Developer runs git push ]
           ↓
[ Same Slop Court trial ]
           ↓
[ Additional network impact analysis ]
           ↓
[ Push allowed only if clean ]
```

## Installation

```bash
python scripts/workshop.py court bailiff install
```

This creates:
- `.git/hooks/pre-commit` (755 permissions)
- `.git/hooks/pre-push` (755 permissions)

## Consequences

### Positive
- **Zero slop policy enforced at Git level**
- **Unanimous acquittal required** (no partial commits)
- **Audit trail via cryptographic docket**
- **Prevents "fix it in prod" mentality**

### Negative
- Initial developer friction
- Occasional false positives (mitigated by exemption pragmas)
- CI pipeline must also pass (no bypass)
